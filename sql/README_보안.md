# 비밀번호 보안 — 실행 순서

## 지금 뭐가 문제였나

로그인 화면이 뜨기 **전에** 브라우저가 `users` 표를 통째로 내려받고 있었고,
그 표에 비밀번호가 그냥 글자로 들어 있었습니다.
비밀번호 대조도 브라우저 안에서 했습니다.

즉 **해킹이 필요 없습니다.** 주소만 알면 누구나 F12 → 네트워크 탭에서
전 직원 아이디·비밀번호를 그대로 볼 수 있었고, 그걸로 본사 계정에 로그인할 수 있었습니다.

## 바뀐 것

- 로그인 전에는 서버에서 아무 데이터도 안 받아옵니다.
- 비밀번호는 `user_secrets` 표에 **bcrypt 해시**로만 저장되고, 이 표는 웹 키로 한 줄도 못 읽습니다.
- 아이디·비밀번호 대조와 비밀번호 변경은 전부 서버 함수(RPC)에서 합니다.
- 로그인 실패가 10분에 30번 넘으면 그 아이디는 잠시 막힙니다.

## 실행 순서 (이 순서대로)

1. **코드 먼저 올리기** — `git pull` → `git push origin main`, 사이트 반영 확인
   - 이 시점에는 아무것도 안 바뀝니다. 서버 함수가 아직 없으니 예전 방식으로 그냥 로그인됩니다.
2. **`sql/auth_stage1.sql`** — Supabase → SQL Editor에 붙여넣고 Run
   - 비밀번호가 해시로 복사되고 서버 함수가 생깁니다.
   - `users.password` 칼럼은 아직 그대로라 **여기까지는 아무것도 안 깨집니다.**
3. **전 분원 로그인 확인** — 6~7개 분원 계정으로 실제로 로그인해 보기
   - 안 되는 계정이 있으면 여기서 멈추고 알려주세요. `auth_stage1.sql` 맨 아래 되돌리기 SQL로 원복됩니다.
4. **`sql/auth_stage2_drop_password.sql`** — 확인 끝난 다음에 Run
   - `users.password` 칼럼을 없앱니다. 이때부터 브라우저로 비밀번호가 아예 안 내려갑니다.
   - 옛날 JS가 캐시된 사람은 **Ctrl + F5** 한 번 하면 됩니다.

## 아직 남은 것 (다음 단계)

지금 고친 건 **비밀번호**입니다. 학생 명단·상담이력 같은 나머지 표는
아직 웹 키만 있으면 로그인 없이도 읽힙니다.
그건 Supabase Auth로 옮겨야 제대로 막히고, 전 분원 로그인이 한 번에 바뀌는 작업이라
날 잡고 따로 해야 합니다.
